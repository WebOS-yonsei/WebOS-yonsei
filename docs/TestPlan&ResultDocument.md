# 미디어 웹 애플리케이션 테스트 플랜 및 결과 문서

## 1. 소개

이 문서는 미디어 웹 애플리케이션 프로젝트의 테스트 플랜을 포함한다. 주요 목표는 시스템이 명시된 기능 요구사항 및 비기능 요구사항을 충족하는지 검증하는 것이다.
이 플랜에는 다음 사항이 포함된다:

1. 요구사항을 검증하기 위한 테스트 시나리오 및 테스트 케이스 도출
2. 도출된 테스트 시나리오/테스트 케이스 작성
3. 테스트 수행 계획 및 결과 문서화

## 2. 목적

이 테스트 플랜의 목적은 명세된 요구사항에 따라 시스템이 개발되었는지를 검증하는 것이다. 이를 위해 다양한 테스트 전략을 수립하고, 유닛 테스트, 인수 테스트, 시스템 테스트를 실행한다.

## 3. 테스트 범위

### - 필수 구현 기능

1. 실시간 시스템 자원 현황 시각화 (CPU, 메모리 등)
2. 미디어 재생 목록 제공
3. 일반 미디어 재생 기능
4. 미디어 이어보기 기능
5. 사용자 식별 기능

### - 심화 구현 기능

1. 등급(연령)별 시청 콘텐츠 차등 적용
2. 네트워크 상태에 따른 미디어 재생시 화질 변화 기능(Adaptive Streaming)
3. 프로필 식별 기능 (한 프로필 마다 최대 한 명만 사용 가능, 한 계정당 최대 3개의 프로필 존재)

## 4. 테스트 전략

### 유닛 테스트

- 각 모듈의 기능을 postman과 [swagger](https://github.com/WebOS-yonsei/WebOS-yonsei/tree/main/docs/webos-server-swagger.html)를 통해 개별적으로 테스트한다.

### 인수 테스트

- 각 컨트롤러별로 스프링에서 작성된 테스트 코드를 통해 인수 테스트를 수행한다.
- 링크: [인수 테스트 코드 바로가기](https://github.com/WebOS-yonsei/WebOS-yonsei/tree/main/server/src/test)

### 시스템 테스트

- 웹 브라우저와 TV를 이용하여 전체 시스템을 테스트한다.

## 5. 시스템 테스트 시나리오 및 테스트 케이스

### 5.1 테스트 시나리오 1: 사용자 및 프로필 식별 기능

#### 테스트 케이스 1.1: 사용자 로그인 및 프로필 관리

- **설명**: 사용자가 로그인하고, 프로필을 생성, 선택, 종료하는 과정을 테스트한다.
- **단계**:
  1. 로그인 페이지로 이동한다.
  2. 유효한 사용자명과 비밀번호를 입력한다.
  3. '로그인' 버튼을 클릭하여 로그인한다.
  4. 프로필을 생성한다.
  5. 생성한 프로필을 선택한다.
  6. 프로필에서 로그아웃한다.
- **기대 결과**: 사용자가 정상적으로 로그인되고, 프로필을 생성, 선택, 종료할 수 있다.

#### 테스트 케이스 1.2: 프로필 동시 사용 제한 및 최대 프로필 수 제한

- **설명**: 한 프로필이 동시에 여러 기기에서 사용될 수 없는지 확인하고, 한 계정당 최대 3개의 프로필만 생성할 수 있는지 확인한다.
- **단계**:
  1. 동일한 프로필로 두 기기에서 로그인 시도한다.
  2. 첫 번째 기기에서 정상적으로 로그인된 후, 두 번째 기기에서 로그인을 시도한다.
  3. 동일한 계정으로 3개의 프로필을 생성한다.
  4. 네 번째 프로필을 생성 시도한다.
- **기대 결과**: 두 번째 기기에서 로그인 시도가 차단되고, 네 번째 프로필 생성 시도가 차단된다.

### 5.2 테스트 시나리오 2: 실시간 시스템 자원 현황 시각화

#### 테스트 케이스 2.1: CPU 및 메모리 사용량 시각화

- **설명**: 시스템의 CPU 및 메모리 사용량을 실시간으로 시각화한다.
- **단계**:
  1. 사용자 계정으로 로그인 후 프로필로 진입한다.
  2. 시스템 자원 현황 페이지로 이동한다.
  3. CPU 및 메모리 사용량이 실시간으로 업데이트되는지 확인한다.
- **기대 결과**: CPU 및 메모리 사용량이 정확하게 시각화된다.

### 5.3 테스트 시나리오 3: 미디어 재생 목록 제공 및 필터링

#### 테스트 케이스 3.1: 재생 목록 불러오기 및 등급별 필터링

- **설명**: 사용자의 미디어 재생 목록을 제공하고, 사용자의 연령에 따라 시청 가능한 콘텐츠를 필터링한다.
- **단계**:
  1. 사용자 계정으로 로그인 후 프로필로 진입한다.
  2. '재생 목록' 페이지로 이동한다.
  3. 재생 목록이 올바르게 불러와지는지 확인한다.
  4. 사용자 연령에 따라 콘텐츠가 필터링되는지 확인한다.
- **기대 결과**: 사용자의 미디어 재생 목록이 정확하게 표시되고, 연령에 맞게 콘텐츠가 필터링된다.

### 5.4 테스트 시나리오 4: 일반 미디어 재생 및 화질 적응

#### 테스트 케이스 4.1: 미디어 재생 및 네트워크 상태에 따른 화질 변화

- **설명**: 선택한 미디어를 재생하고, 네트워크 상태에 따라 화질이 적절히 변경되는지 확인한다.
- **단계**:
  1. 미디어 재생 목록에서 항목을 선택한다.
  2. '재생' 버튼을 클릭한다.
  3. 미디어가 정상적으로 재생되는지 확인한다.
  4. 네트워크 상태를 조정하여 화질이 변경되는지 확인한다.
- **기대 결과**: 선택한 미디어가 정상적으로 재생되고, 네트워크 상태에 따라 화질이 적절히 변경된다.

### 5.5 테스트 시나리오 5: 미디어 이어보기 및 시청 시간 기록 기능

#### 테스트 케이스 5.1: 미디어 이어보기 및 시청 시간 기록

- **설명**: 중단된 미디어를 이어서 재생하고, 사용자가 특정 비디오를 본 시간을 기록한다.
- **단계**:
  1. 미디어 재생 중 중단(종료)한다.
  2. 시청 시간을 기록한다.
  3. 다시 미디어를 선택하고 '이어보기' 버튼을 클릭한다.
  4. 중단된 지점부터 재생이 이어지는지 확인한다.
- **기대 결과**: 시청 시간이 정확하게 기록되고, 중단된 지점부터 미디어가 이어서 재생된다.

## 6. 테스트 수행 계획

### 6.1 테스트 일정

- 테스트 시작일: 개발 시작 시점
- 테스트 종료일: 2024-06-09

### 6.2 테스트 자원

- 테스트 담당자: 팀원 모두
- 테스트 도구:
  - 일반 웹 테스트: 웹 브라우저 (Chrome, Firefox 등)
  - TV 연결 테스트: LG StanbyME TV

### 6.3 배포 및 테스트 환경 설정

- 웹 배포 과정:

  1. 프로젝트를 빌드하여 웹 서버에 배포 가능한 형태로 패키징한다.
  2. 패키징된 파일을 웹 서버(Firebase, GCP)에 업로드한다.
  3. 웹 서버에서 애플리케이션을 배포하고 실행한다.
  4. 브라우저를 통해 애플리케이션에 접속하여 정상적으로 실행되는지 확인한다.

  - 배포 URL: [백엔드 배포 사이트 바로가기](https://webos-yonsei.shop)
  - 배포 URL: [프론트엔드 배포 사이트 바로가기](https://webos-yonsei.web.app)

- TV 배포 과정:
  1. 프로젝트를 빌드하여 TV에 배포 가능한 형태로 패키징한다.
  2. 패키징된 파일을 LG StanbyME TV의 개발자 모드에서 업로드한다.
  3. TV에서 애플리케이션을 설치하고 실행한다.
  4. 애플리케이션이 정상적으로 실행되는지 확인한다.
